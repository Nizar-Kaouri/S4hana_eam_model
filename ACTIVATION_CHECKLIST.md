# Activation checklist

> **Nothing in this repository has been activated.** No SAP system was available while
> writing it. Every module is `draft-unverified`, tested release: `none (draft, 2025 assumed)`.
> This file is the plan for the first import into a real SAP S/4HANA 2025 system.

The order in the tables below is computed from the references between objects (the same
algorithm `build_package.py` uses for the `ACTIVATION_ORDER.txt` inside every customer ZIP).
Numbers are global positions in the full library; a customer build with fewer modules keeps
the same relative order.

## 0. Before you import

- [ ] System is S/4HANA 2025 (SAP_BASIS 816). Record the exact FPS/SP in `BATCH_REPORT.md`.
- [ ] Package `ZEAM_VDM` (or the customer package) exists, with a transport request.
- [ ] abapGit (standalone `ZABAPGIT` report or the ADT plug-in) is installed. For the ADT route see `ADT_SETUP.md`.
- [ ] Every SAP view listed below exists and is released for use (C1). Open each one in ADT
      (Ctrl+Shift+A) and compare its element list with the elements we use.
      **Do this first; it settles most HIGH items in `BATCH_REPORT.md`.**
- [ ] For every SAP view our DCLs inherit from (`I_Equipment`, `I_FunctionalLocation`,
      `I_MaintenanceNotification`, `I_MaintenanceOrder`, ...), open its access control and write
      down the elements it uses.
- [ ] Import batch by batch (build with only the modules of the batches done so far). That
      keeps each activation log small.

## 1. Order and status per batch

Activate in the listed order. Mass activation of a whole table works too. Text and
dimension views reference each other through associations, so activate them together if
one fails on its own. An inheriting role needs the role it inherits from to be active first.

## 2. Functional smoke checks after activation

- [ ] Data preview (F8) on every basic view returns rows; the row count is plausible against
      the SAP table (e.g. `ZEAM_I_Equipment` against `EQUI`, `ZEAM_I_MaintOrder` against `AUFK` with `AUTYP = 30`).
- [ ] Value help views show descriptions in the logon language.
- [ ] A user without plant authorization sees fewer rows than an administrator (DCLs are active).
- [ ] Every `ZEAM_C_*Q` opens in an analytical preview of a service binding or in `RSRTS_ODP_DIS`.
- [ ] Link views: path fields (e.g. `FunctionalLocationLabelName`, `MaintenanceOrderType`) are filled.
- [ ] Reporting (Batch 4): downtime hours of a sample breakdown notification match a manual
      calculation; order costs of a sample order match `KOB1` / order cost display before settlement.
- [ ] Run ATC on the package with the customer's check variant. Record findings in `BATCH_REPORT.md`.

## 3. After a successful activation

1. Fix every error **in this git repository**, never only in the system. Then re-run the
   quality gates (`npm run check`).
2. Remove the `TODO-VERIFY` marker of every item that was confirmed, and record the result
   in `BATCH_REPORT.md` under *Verification log*.
3. Set `status` in each `module.json` to `activated` (or `tested` once ABAP Unit and the smoke
   checks pass), and set `tested_release` to the exact release, e.g.
   `S/4HANA 2025 FPS01 (SAP_BASIS 816 SP01)`. Also remove `"phase": "no-system"` from
   `library.json`.
