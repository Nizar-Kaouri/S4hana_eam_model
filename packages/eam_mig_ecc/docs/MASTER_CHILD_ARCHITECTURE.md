# Master and child migration architecture

Use native SAP tables -> B (Basic) -> I (Interface/Composite) -> C (Consumption). Keep a unique master at its documented grain; do not flatten repeating children into the master. Preserve complete child keys, language, organizational level, validity periods and ECM counters.

## Selected population

`customer/parent-relationships.json` lists the exact parent keys for this pack. The customer preparation project first respects explicit approved full-key selections, then scopes children to the prepared parent population. Parent full-key duplicates stop preparation. Repeated parent references are permitted only when their full identities differ, such as operation routing references or interval records; payload rows are never deduplicated. The preparation audit records row counts before and after each scope step.

A parent scope is not an effectivity evaluation: run documented validity/ECM preparation before selecting the final active records. Generic polymorphic object exports, financial balances and independently approved reference datasets retain their own explicit contracts. Source IDs must be mapped when target numbering changes.

## Address and status handling

Equipment and functional locations use ILOA.ADRNR; FI customers, suppliers and banks use their native ADRNR field. The main record uses the standard ADRC full key DATE_FROM=00010101 and NATION blank through an optional to-one association. Missing standard addresses preserve the master and set HasStandardAddress blank. All date and international versions are separate reference child exports. Target address numbers are generated by SAP.

CO cost/profit center address and communication fields are scalar attributes of their native master interval records. Do not assume every object owns a postal address. SD sales, delivery and billing partner exports use the native VBPA.ADRNR document address. These addresses may differ from customer masters; no customer-address fallback is invented. Header partners retain item 000000; repeating partners and their address versions stay separate from the document master.

QM inspection lots/notifications, PS projects/WBS/networks, PP production orders and CO internal orders have separate active JEST status reference exports joined by actual OBJNR. Preserve StatusCode and object business keys. System statuses are recreated by SAP processes and must not be posted from JEST. User statuses require a separate mapping and a supported target business operation; the reference export is not a posting adapter.

Use consistent full cutover snapshots when dependent table changes are not covered by a verified change-capture strategy. Read the field catalogue and map added extraction attributes against the installed target migration template or supported interface; no target fields or compatibility are implied by source extraction fields.
