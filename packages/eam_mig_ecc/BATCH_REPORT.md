## Batch 1 - EAM migration pilot (source, mapping, reconciliation)

**Date:** 2026-10-10 · **Status:** draft-unverified · **Tested release:** none (draft, ECC 6.0 on NetWeaver 7.40 SP08 assumed)

Direction changed from reporting to migration (old SAP ERP → S/4HANA; full + delta extraction, mapping,
reconciliation). The reporting products stay as an optional analytics add-on.

### Generated

- 44 classic CDS views on ECC tables in 13 modules: work center, functional location, equipment, measuring
  point, measurement document (incl. last reading per point), task list (incl. current version), maintenance
  plan (incl. cycles and call history), open notification, open order (operations, components), object status,
  classification, object partner, long text index.
- 13 `mapping.json` files (element → S/4HANA field, rule, compare flag, business key / numbering, scope,
  load order, key maps provided / external, reconciliation) and the generated pages in `docs/mapping/`,
  `docs/MIGRATION_SEQUENCE.md` (8 load levels) and 45 value-map / key-map CSV templates.
- Tools: `tools/validate_mapping.py` (X1-X6), `tools/gen_mapping.py`, `tools/mig_reconcile.py` (counts / records),
  validator rule M12 (classic views, SQL view names, no DCL on ECC), SQL view name rewrite + length check in
  `build_package.py`, mapping files in the ECC ZIP, one-system rule in `build_bundle.py`.

### Offline checks run

- `tools/check_all.py`: all 12 products pass (abaplint 2.120.71 with 7.40 SP08 syntax for this product, M1-M12, X1-X6).
- Full ECC build with namespace `/ACME/`: 44 objects, SQL view names rewritten (`/ACME/EQ`), abaplint 0 issues in 89 files.
- 34 unit tests OK, incl. 10 for the reconcile tool (value maps, key maps, scope filter, leading zeros, exit
  codes) and 5 for the migration builds.
- Negative test: a key map used before the object that provides it loads is rejected (X4).
- **Nothing activated, extracted or loaded on a system.**

### Design decisions (please confirm)

1. **XGEN-D01 - no CDS access control on extraction views.** They must return every record; protect them via
   the extraction channel. Deviates from hard rule 5 (DCL for every view) on purpose.
2. **Tables instead of released views on ECC** (hard rule 1 updated); element names follow the S/4HANA views.
3. **Business keys instead of internal IDs** (work center name + plant, characteristic / class names); object
   numbers (OBJNR) are only used to join status, partners and texts.
4. **Scope by flags, not filters:** extraction views return everything; scope filters live in the mapping;
   count views count the scope.
5. **Transactional data = open documents only** (open notifications, open orders, last counter reading);
   history stays in the old system / archive.
6. **Back references are follow-up steps** (standing order on technical objects, order number on the
   notification), so the load order has no cycle.
7. **Reconciliation on S/4HANA reads SAP released views directly**, not the `ZEAM_` analytics views, so the
   migration package does not depend on the analytics product.

### Open risks (top)

- Every `M01` item: Migration Cockpit object names and structure fields are not confirmed; targets are the
  S/4HANA table fields.
- XGEN-002: literal comparisons in left outer join ON conditions and simple CASE on 7.40 SP08 (used for
  the status flags). Fallback: separate status views joined by the extraction tool.
- XGEN-003 / `@Analytics.dataExtraction` delta on a date element: availability on 7.40 SP08 (likely 7.50+)
  and day granularity; plan a full reload at cutover.
- XTL-003/004: task list versions (ZAEHL) - the latest-version logic must be confirmed with change numbers.
- XLT-G01: long text content needs an ABAP extractor (`READ_TEXT`).

## Batch 2 - restructured into basic → composite → consumption

**Date:** 2026-10-10 · **Status:** draft-unverified · **Tested release:** none (draft, ECC 6.0 on NetWeaver 7.40 SP08 assumed)

Restructured on request to the layering used in customer projects: the load program reads only the consumption
views, which deliver values already translated to S/4HANA values. Views only - no load program.

### Changes

- **Basic** (42): exactly one table per view (status flags as one view per status code instead of literal ON
  conditions; work center filtered to type 'A' in the basic view).
- **Composite** (21): business objects assembled from basic views (equipment, functional location, task list
  current version, operations, orders, notifications, plans with restart point, last reading, classification).
- **Consumption** (25 + 13 count views): `ZEMX_C_*Mig`, scope applied, only migrated fields, every value / key field
  translated through the new mapping table `ZEMX_MAP` (`coalesce`, no entry = unchanged), `Legacy*` keys; the
  only layer with extraction / delta annotations. Count views count the consumption views.
- **Naming:** SAP VDM convention - `I_` for basic and composite, `C_` for consumption (`R_` dropped in both
  migration products; `layer_prefixes` / `consumption_suffixes` in `library.json`).
- **Mapping files** now document the consumption interface (structures, keys, scope filter, fields, not delivered
  fields); `validate_mapping` X1-X6 checks them against the view sources (map joins, coalesce, scope filter, keys).
- **Reconciliation** compares translated values directly (`source_values: target`); maps are only needed for
  old-value exports (`--translate`).
- **Tooling:** object type TABL (build, activation order, validator, checklist), layer rules configurable.

### Offline checks run

- `tools/check_all.py`: all products pass; abaplint 0 issues in 204 files of this product (7.40 SP08 syntax).
- 36 unit tests OK, incl. layer order (upper layers read only lower layers, basic views read one table) and the
  build with automatic `core` / `work_center` dependencies and `ZEMX_MAP` activated first.
- **Nothing activated, extracted or loaded.**

### Design decisions (please confirm)

1. **Mapping on ECC** (`ZEMX_MAP`): key maps of renumbered objects are written back after each load level.
2. **Reference units are not mapped** (weight, work, duration, base unit) so that quantities keep their unit
   reference; unit of measure customizing is transported.
3. **Float values** (measuring point ranges, readings, cycles, numeric characteristics) are delivered in the SI
   unit; the load program converts them (`convert:float_si_to_unit`).

### Open risks (top)

- XGEN-004: `coalesce` of `TargetValue` (CHAR 50) with shorter key fields and the CHAR comparison in the map join
  on 7.40 SP08; fallback: cast the map value per field.
- XGEN-002: literal `MapName = '...'` in the left outer join ON condition; fallback: one basic view per map name.
- Each `M01` item: target fields assumed equal to the ECC table fields - confirm against the load program's
  posting interface.

## Batch 4 - associations instead of joins

**Date:** 2026-10-10 · **Status:** draft-unverified

Following the SAP VDM practice, relationships are modelled as associations:

- **Basic views** declare 37 associations to other basic views (location data, work centers, status flags,
  characteristics, classes, operations) and expose them.
- **Composite views** read related data with path expressions; inner joins remain only where they decide which
  rows exist (current EQUZ segment, latest task list version, PLAS ↔ PLPO, last reading, QMIH / AFIH / AFKO / AFVV).
  No left outer joins remain (checked by a unit test).
- **Consumption views** of child structures reach their parent through an association for the scope filter
  (e.g. `ZEMX_C_MaintOrderOperationMig` → `_MaintOrder`) instead of an inner join.
- New item XGEN-005 [H]: associations with `$projection` in the ON condition and path expressions (with alias,
  in CASE, in WHERE) on 7.40 SP08 classic views.
