### Design decisions (please confirm)

1. **Values from the Universal Journal only.** Every `I_JournalEntryItem` line with an asset number is
   an asset posting. There is no separate asset-value view, so the model depends on one well-known
   released view. Planned depreciation is out of scope for now.
2. **Value category** (acquisition / retirement / transfer / depreciation / other). Depreciation
   comes from the business transaction type of the depreciation run (AT-003). The rest comes from the
   first digit of the asset transaction type (SAP standard ranges 1xx / 2xx / 3xx, AT-004). Customer
   transaction types outside these ranges end up in "other".
3. **Net book value = balance-sheet postings on the asset up to the key date** (G/L account type `X`).
   This depends on the customer's account determination (AB-R01) and has to be reconciled against the
   asset balance report AR01 / FAGL_ASSET_EXPLORER on the first system.
4. **All ledgers and depreciation areas are kept as characteristics.** The queries offer a single-value
   filter on the ledger; nothing is hard-coded to `0L` (unlike the EAM cost report).
5. **Asset master assignments** (cost center, plant, profit center) are taken as today's values from
   `I_FixedAsset` (FA-004). Time-dependent history is not modeled.
