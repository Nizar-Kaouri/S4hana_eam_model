## Batch 1 - EAM migration pilot (reconciliation side)

**Date:** 2026-10-10 · **Status:** draft-unverified · **Tested release:** none (draft, 2025 assumed)

- Field lists generated from the `compare` flags of the ECC mapping files; `validate_mapping` X5 keeps both
  sides aligned (same dimensions, same element names, same business key).
- Released views and element names are the ones already used by `packages/eam` (same verification items).
- Offline checks: `tools/check_all.py` passes (abaplint, M1-M12). Nothing activated.

### Design decisions (please confirm)

1. **TGEN-D01 - no CDS access control:** reconciliation must see every migrated record; grant the views to the
   migration role only.
2. **No dependency on the analytics product:** the views read `I_Equipment`, `I_MaintenanceOrder`, ... directly.

### Open risks

- TTL-001: `I_MaintenanceTaskList` has one row per version; after a fresh load there is one version per task list.
- TNO-001 / TOR-001: notifications and orders created on S/4HANA after the load must be excluded from the comparison.

## Batch 2 - naming aligned with the SAP VDM convention

Count views renamed `ZEMT_R_*Count` → `ZEMT_I_*Count` (composite views use `I_`). They are compared with the ECC consumption views (`ZEMX_C_*MigCount`, `ZEMX_C_*Mig`), which deliver translated values.
